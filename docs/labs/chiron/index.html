Chiron

A software factory for changes you can verify.

Chiron, formerly Factory, takes a repository and a description of the behavior you need. One agent builds the change. Another writes tests from the requirements and public interfaces, without seeing the implementation. You get a candidate commit and the evidence for it: what was checked, what failed, and what remains uncertain.

Repository How it works

Four roles, two independent authors

The Coder and Tester work from different briefs. The Validator owns acceptance; the Orchestrator watches the work and flags drift.

Validator
Turns the request and repository constraints into separate briefs, then judges the result against the intended behavior.
Coder
Implements against the brief and public interfaces without seeing the Tester’s independent checks.
Tester
Writes checks from the behavior and interfaces without seeing the Coder’s implementation.
Orchestrator
Watches for drift, missing evidence, and work that goes past the brief.

Review the exact change

Chiron records the starting commit and runs the project’s checks against an exact candidate. You can inspect which behavior was exercised, which checks passed, and where the evidence falls short. Passing checks inform the Validator’s decision; they don’t merge or deploy the code.

In an existing system, repository constraints and public contracts shape the work. A small, well-bounded change can move quickly. A change with wider consequences needs evidence that the surrounding behavior still holds.

Start with a behavior

Describe what a caller or user should observe, then point Chiron at the repository. Choose the supported agent and model for each role, or use local defaults.

factory run example 'Describe the required behavior' --repo /path/to/repo
